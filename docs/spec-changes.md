# Changes to SPEC v0.1

Decisions taken during implementation that changed a **MUST** in `SPEC.md`. Each was approved before merge.

| Date | Section | Change | Reason |
|---|---|---|---|
| 2026-11-18 | §4.2, §13.1 | Agent ClusterRole also reads `policies.kyverno.io/v1` validatingpolicies, namespacedvalidatingpolicies, imagevalidatingpolicies, namespacedimagevalidatingpolicies. | Kyverno 1.20 removed execution of legacy `kyverno.io/v1` policies; without this the Security page shows nothing for current Kyverno installs. |
| 2026-11-18 | §4.2 | Read-only `configmaps` in the kubescape/polaris extras. | Polaris aborts without listing ConfigMaps; §4.2 only forbids ConfigMap writes. |
| 2026-11-18 | §11.1 | Olympos Vault policy adds `update` on `auth/approle/role/olympos/secret-id` and `.../secret-id-accessor/destroy`. | Monthly secret_id rotation is impossible once the root token is gone. No read on secret data is added. |
| 2026-11-18 | §12.3.4 | The kube-bench Kyverno `PolicyException` is opt-in (`bench.kyverno.legacyException`, `bench.kyverno.policyRefs`) instead of auto-rendered. | Kyverno 1.20 rejects `kyverno.io/v2` exceptions; `policies.kyverno.io/v1` exceptions must name each policy. |
| 2026-11-18 | §10.3 | §10.3 destinations: S3 (incl. S3-compatible via endpoint override; static access key, delete refused by policy) and NFS (directory below a volume mounted under `backup.nfsRoot`; the server can technically delete there, always reported as a can-delete warning; retention by storage snapshots / WORM) added; Azure endpoint override exposed. Retention stays lifecycle rules (S3: filtered by tag `olympos-tier`). | On-prem and non-Azure installs need a backup target. The server is still the only writer and has no delete code path except the probe delete check. |
| 2026-11-19 | §7 | In `e2e-tls` mode a target without TLS no longer falls back to plaintext with a password: PostgreSQL only with SCRAM-SHA-256 (auth request checked before the password is sent), ClickHouse and Vault refused with a clear error; `compressed` mode unchanged; `tls.missing` opens in every case. | v1 release fix F1: ClickHouse native and PostgreSQL MD5/cleartext would expose the password to the agent and the node network. |
| 2026-11-19 | §2.1, §6 | Dev login, the local Key Vault and dev-mode config are compiled only into development builds (`-tags dev`); release builds return 404 for `/auth/dev-login` and refuse `devMode`. | v1 release fix F6: a runtime flag must never become an auth bypass. |
| 2026-11-19 | §11.4, §11.5 | New change request state `applying` (two transactions around the Vault call, vault lock held across them) and a reconciler that settles stuck requests from KV metadata (`applied` / `failed` with `apply_unknown` or `conflict`); drift skips paths in `applying`. | v1 release fix F4: a commit lost after the Vault write left the request `pending` and drift reported Olympos' own write as unmanaged. |
| 2026-11-19 | §2, §17 | v0.1 is single-instance: the Helm chart refuses `replicas > 1` without `experimental.multiReplica`, uses `Recreate`; a newer live instance on the same database is not ready. | v1 release fix F5: tunnels only open on the replica the agent is connected to. Replica-to-replica forwarding is planned for v0.2. |
| 2026-11-19 | §2.1, §10, §20 | Olympos' own database: bundled PostgreSQL 16 in the Helm chart (default) or the local one over the Unix socket (systemd); built-in non-deletable `olympos-self` backup job with Needs-attention until configured; KEK purge-protection check; downgrades of the schema refused. | Owner decision (F17): state must survive a lost host. |
| 2026-11-19 | §4.5 (new), §6, §10, §12 | Reconnect semantics: generations on inventory messages with resync on gaps; agent buffer (16 MiB) for kube-bench results with idempotent `seq` ingest; runs failing on a disconnect are retried (max 3, half the interval) or `missed`; `agent.offline` after 5 min, one `agent.online`, new `agent.flapping`. | Owner decision (F18): reliability and consistency first. |
| 2026-11-19 | §2, §17 | systemd deployment mode: static binary, `.deb`/`.rpm` (nfpm) with a hardened unit (exposure 1.4), `/etc/olympos/config.yaml` 0640 root:olympos, tools under `/usr/lib/olympos/bin`, pg_dump from PGDG (`backup.pgDumpDir` takes ':'-separated layouts incl. `{major}`); UI TLS from files and SIGHUP reload of certificates; internal-CA gateway certificate renews itself; `migrate`, `check-config`, `version` subcommands. | Owner decision (F16). |
| 2026-11-19 | §13.5 (new), §14 | Sensitive data in ConfigMaps: scanned on the agent (gitleaks library + key-name rules), report without values, findings `sensitive-data`, event `sensitive_data.found`, Security › Sensitive data. | v1 release fix F2, pairs with deviation #2 (ConfigMap read, approved). |
