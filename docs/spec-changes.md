# Changes to SPEC v0.1

Decisions taken during implementation that changed or extended a **MUST** in `SPEC.md`. Every row has an
owner decision. Part 1 lists the deviations found while building M1–M6 (reviewed against SPEC on 2026-11-19,
"v1 release fixes"); part 2 the changes made by those fixes.

## 1. Deviations (M1–M6)

| # | Date | Section | Change | Reason | Approval |
|---|---|---|---|---|---|
| 1 | 2026-11-18 | §4.2, §13.1 | Agent ClusterRole also reads `policies.kyverno.io/v1` validatingpolicies, namespacedvalidatingpolicies, imagevalidatingpolicies, namespacedimagevalidatingpolicies. | Kyverno 1.20 removed execution of legacy `kyverno.io/v1` policies; without this the Security page shows nothing for current Kyverno installs. | Approved (owner, 2026-11-18) |
| 2 | 2026-11-18 | §4.2 | Read-only `configmaps` in the kubescape/polaris extras. | Polaris aborts without listing ConfigMaps; §4.2 only forbids ConfigMap writes. | **Approved** (v1 review); paired with F2: the agent scans ConfigMaps for credentials and reports them as findings, values never leave the cluster |
| 3 | 2026-11-18 | §11.1 | Olympos Vault policy adds `update` on `auth/approle/role/olympos/secret-id` and `.../secret-id-accessor/destroy`. | Monthly secret_id rotation is impossible once the root token is gone. No read on secret data is added. | Accepted in the v1 review (no change requested) |
| 4 | 2026-11-18 | §12.3.4 | The kube-bench Kyverno `PolicyException` is opt-in (`bench.kyverno.legacyException`, `bench.kyverno.policyRefs`) instead of auto-rendered. | Kyverno 1.20 rejects `kyverno.io/v2` exceptions; `policies.kyverno.io/v1` exceptions must name each policy. | Approved with #1 (owner, 2026-11-18) |
| 5 | 2026-11-18 | §10.2 | A PostgreSQL backup is one stored (uncompressed) **zip**: `globals.sql` + one `pg_dump -Fc` per database. | A streamed tar needs every entry size up front; zip streams entries of unknown size. | Accepted in the v1 review (design decision) |
| 6 | 2026-11-18 | §10.2 | The ClickHouse zip uses Deflate; types ch-go cannot decode are exported as `.rowbinary`. | Native data arrives uncompressed; some types have no ch-go decoder. | Accepted in the v1 review (design decision) |
| 7 | 2026-11-18 | §7 | In `e2e-tls` mode a target without TLS fell back to plaintext for PostgreSQL and ClickHouse (with `tls.missing`). | §7 allowed the run with a finding. | **Superseded by F1** (blocker): no password crosses a non-TLS connection |
| 8 | 2026-11-18 | §1.1 | Plain pgx in every module instead of sqlc. | Modules were built in parallel; one shared generated package would conflict ("suggested" in §1.1). | Accepted in the v1 review (design decision) |
| 9 | 2026-11-18 | §1.2 | The server image contains an exec-only `/bin/sh` shim (`olympos-sh`). | `pg_dumpall` finds `pg_dump` through `popen()`; distroless has no shell. The shim runs one absolute program and rejects any shell syntax. Not needed on a normal OS (systemd install). | Accepted in the v1 review (fix) |
| 10 | 2026-11-18 | §6 | `/auth/dev-login` and the local Key Vault behind a runtime `devMode` flag. | Lab and development. | **Superseded by F6** (blocker): compiled only into `-tags dev` builds |
| 11 | 2026-11-18 | §4.4 | Extra `--set` lines for the generated install command (`OLYMPOS_AGENT_INSTALL_SETS`). | Image mirrors in isolated networks; local images in the lab. | Accepted in the v1 review (no change requested) |
| 12 | 2026-11-18 | §10.3 | Destinations: S3 (incl. S3-compatible via endpoint override; static access key, delete refused by policy) and NFS (directory below a volume mounted under `backup.nfsRoot`) besides Azure Blob; Azure endpoint override exposed. Retention stays lifecycle rules (S3: filtered by tag `olympos-tier`). | On-prem and non-Azure installs need a backup target. | Approved (owner request) |
| 13 | 2026-11-18 | §0 (6), §10.3 | On NFS the server can technically delete files; the destination test reports it as `can_delete`. Code only deletes its own `.partial` and probe files. | A file system has no "write but not delete" permission. | **Approved with conditions** (v1 review): docs say NFS needs storage-side snapshots/WORM; the warning stays permanently visible on NFS destinations (list and dialog), whatever the last test said |
| 14 | 2026-11-18 | §13.3 | Registries without a matching credential are tried anonymously first. | Public registries (`cgr.dev`, `reg.kyverno.io`) were flagged "Missing credential"; an anonymous pull is harmless. | **Approved** (v1 review) |
| 15 | 2026-11-18 | §7, §11 | A Vault/OpenBao without TLS (plain HTTP) is refused with a clear error, no silent fallback; `compressed` transfer mode accepts the risk. | Root token, AppRole token and secret values would cross the agent in clear. | **Approved** (v1 review); F1 applies the same rule to PostgreSQL and ClickHouse |
| 16 | 2026-11-18 | §4.2, §13 | The agent sends Kyverno policy objects (spec), NetworkPolicy specs, namespace labels and, per namespace, up to 50 workloads' pod template labels and ports (size-capped). | Needed to show policies and simulate connections. Only §4.2 read-only resources. | **Approved** (v1 review); extended by F3: with the opt-in Secret inventory, stripped pods and ServiceAccounts keep the **names** of the Secrets they reference |
| 17 | 2026-11-18 | §13.3 | When a digest is not in its registry (locally built, retagged), the registry image with the same tag is scanned and marked "Scanned by tag"; `vuln.critical` only for digest scans. | Public images should be scanned too. | **Approved** (v1 review): the UI labels such results "may differ from the running image" |

## 2. v1 release fixes

| Date | Fix | Section | Change | Reason |
|---|---|---|---|---|
| 2026-11-19 | F1 | §7 | In `e2e-tls` a target without TLS never receives a password over plaintext: PostgreSQL only with SCRAM-SHA-256 (the auth request is checked before the password is sent, pgx and pg_dump), ClickHouse and Vault refused with a clear error naming both ways out; `compressed` unchanged; `tls.missing` opens in every case. | ClickHouse native and PostgreSQL MD5/cleartext expose the password to the agent and the node network. |
| 2026-11-19 | F6 | §2.1, §6 | Dev login, the local Key Vault and `devMode` exist only in `-tags dev` builds; release builds return 404 for `/auth/dev-login` and refuse `devMode`; CI checks the release binary's symbols. | A config mistake must never become an auth bypass. |
| 2026-11-19 | F4 | §11.4, §11.5 | Change request state `applying`: two transactions around the Vault call with the vault lock held across them; a reconciler settles stuck requests from KV metadata (`applied` / `failed` `apply_unknown` / `conflict`); drift skips paths in `applying`. | A lost commit after the Vault write left the request `pending` and drift reported Olympos' own write. |
| 2026-11-19 | F5 | §2, §17 | v0.1 is single-instance: the chart refuses `replicas > 1` without `experimental.multiReplica` and uses `Recreate`; a newer live instance on the same database is not ready. Replica-to-replica tunnel forwarding is planned for v0.2. | Tunnels only open on the replica the agent is connected to. |
| 2026-11-19 | F17 | §2.1, §10, §20 | Own database next to the server: bundled PostgreSQL 16 (Helm, default) or local over the Unix socket (systemd); built-in non-deletable `olympos-self` backup, Needs attention until configured; KEK purge-protection check; schema downgrades refused; `docs/restore-olympos.md`. | Owner decision: state must survive a lost host. |
| 2026-11-19 | F18 | §4.5 (new), §6, §10, §12 | Reconnect semantics: generations on inventory messages with resync on gaps; agent buffer (16 MiB) for kube-bench results with idempotent `seq` ingest; disconnected runs retried (max 3, half the interval) or `missed`; `agent.offline` after 5 min, one `agent.online`, `agent.flapping`; offline clusters shown "as of last seen". | Owner decision: reliability and consistency first. |
| 2026-11-19 | F16 | §2, §17 | systemd deployment: static binary, `.deb`/`.rpm`, hardened unit (exposure 1.4), `/etc/olympos/config.yaml`, tools under `/usr/lib/olympos/bin`, pg_dump from PGDG (`backup.pgDumpDir` takes `:`-separated layouts incl. `{major}`); UI TLS from files; SIGHUP reloads certificates; the internal-CA gateway certificate renews itself; `migrate`, `check-config`, `version`. | Owner decision. |
| 2026-11-19 | F2 | §13.5 (new), §14 | Sensitive data in ConfigMaps scanned on the agent (gitleaks library + key names), report without values, findings `sensitive-data`, event `sensitive_data.found`, Security › Sensitive data. | Pairs with deviation #2. |
| 2026-11-19 | F3 | §0 (2), §4.2, §13.6 (new) | Opt-in Secret inventory (`secretsInventory.enabled`, off): `secrets: [list, watch]` only when enabled, metadata-only client, key names from managedFields, reference names from pod specs, findings `k8s-secrets`, Security › Kubernetes secrets. | Owner decision. |
| 2026-11-19 | F7 | §18, §19 | CI (`ci.yml`), e2e + systemd smoke (`e2e.yml`, main + nightly), release (`release.yml`: multi-arch images, packages, SBOMs, cosign keyless, provenance, signed OCI charts). | Supply-chain claims must be verifiable. |
| 2026-11-19 | F9 | §14 | Noisy events are grouped per cluster and scan: `vuln.critical`, `audit.new_findings`, `sensitive_data.found`, `secret.new_findings` send one message with counts and the top 5; the activity log keeps one row per item. | One Slack message per critical CVE floods channels. |
| 2026-11-19 | F19 | §10.4 | Each successful backup run shows ready-to-copy restore commands for that run (download, verify, restore) and links `docs/restore.md`; UI restore to a **new** target (maker/checker) is planned for v0.2. | v0.1 has no restore button. |
